# v0.12 — PCRE2 with prefixed symbols: embeddable next to `libphp.a`

Started 2026-09-17. Level 2 (published crates, every embedder affected):
fresh-subagent meta-analysis, independent review.

## 1. Scope

### Problem

ePHPm embeds vivacity (`ephpm/ephpm#523`: `ephpm composer` calls
`vivacity::run` in-process) and links `libphp.a`. Its E2E jobs fail at link
time: `rust-lld: duplicate symbol: _pcre2_check_escape_8,
_pcre2_default_match_context_8, pcre2_set_max_pattern_compiled_length_8…`.
vivacity's three library crates use the `pcre2` crate (15 patterns:
Composer's `JsonManipulator` with recursive `(?&json)` subpatterns, the
class finder in byte mode with lookbehind and possessive quantifiers, the
version parser, path-repository globs…); `pcre2-sys` builds its vendored
PCRE2 statically when pkg-config finds no `libpcre2-8`, and PHP's
`libphp.a` bundles its own PCRE2 (`ext/pcre/pcre2lib`) with the same
unprefixed symbols. Any static PHP embedder hits this; a system
`libpcre2-8` only papers over it on hosts that have one.

Replacing PCRE is not an option: `regex`/`fancy-regex` have no recursive
subpatterns, and the class finder's byte-mode patterns are ported
character for character from Composer; parity is proven against PCRE.

### Reference

- PCRE2 names every function, type and internal data item through one
  macro: `pcre2.h:869-871` `PCRE2_JOIN` / `PCRE2_GLUE` /
  `PCRE2_SUFFIX(a) PCRE2_GLUE(a, PCRE2_LOCAL_WIDTH)` (public API:
  `pcre2_compile` → `pcre2_compile_8`); `pcre2_internal.h:201`
  `PRIV(name) _pcre2_##name` and `:2084+` `#define _pcre2_x
  PCRE2_SUFFIX(_pcre2_x_)` (internals: `_pcre2_check_escape_8`). sljit is
  compiled `SLJIT_CONFIG_STATIC` (`pcre2_jit_compile.c:61`): its
  functions are `static`, no symbol leaks.
- `pcre2-sys 0.2.10` `build.rs`: pkg-config first unless
  `PCRE2_SYS_STATIC=1` or musl; else `cc` on `upstream/src/*.c` with
  `PCRE2_CODE_UNIT_WIDTH=8`, `PCRE2_STATIC`, `SUPPORT_UNICODE`,
  `SUPPORT_JIT` (except iOS/tvOS/Android/musleabi); `src/bindings.rs`:
  222 `pub fn pcre2_*_8` in `unsafe extern "C"` blocks, no `pub static`.
- `pcre2 0.2.11`: depends on `pcre2-sys`, uses it as `pcre2_sys::*`
  (`ffi.rs:10`); no features. License `Unlicense OR MIT`; PCRE2 itself
  BSD-3-Clause (`upstream/LICENCE`).
- vivacity: `pcre2 = "=0.2.11"` in the workspace, used by
  `vivacity-core`, `vivacity-resolver`, `vivacity-autoload` (never
  `pcre2_sys` directly).

### Constraints

- Same engine, same version (10.x vendored by pcre2-sys 0.2.10), same
  build flags: parity untouched, proven by the unchanged harness suite.
- Always built from the vendored source, never the system library: the
  prefix must be there whatever the host has installed.
- Published to crates.io like the other crates (`cargo install
  vivacity`, ePHPm's `vivacity = "=0.12.0"` must resolve); a `[patch]`
  does not propagate to consumers, hence two crates of our own:
  `vivacity-pcre2-sys`, `vivacity-pcre2`.
- Windows (MSVC), macOS, Linux (glibc and musl) builds and the three CI
  platforms stay green.
- No mention of the AI tooling anywhere (global rule).

### Non-goals

- Upstreaming the prefix as a `pcre2-sys` feature: proposed separately
  to BurntSushi after this ships (a `cfg_attr(feature, link_name)` per
  binding is feasible); the fork is the bridge until then.
- Changing any pattern or the `pcre2` Rust API.
- Making PCRE optional.

### Success criteria (observable)

1. `nm` on the built `libvivacity_pcre2.a` (Linux, macOS): every defined
   global symbol starts with `vivacity_` (137 of them); the check is
   `tools/check-pcre2-symbols.sh`, run in `ci.yml` on both OSes.
2. A link test that fails without the prefix and passes with it: a C
   object defining `pcre2_compile_8`, `_pcre2_check_escape_8` and
   `pcre2_match_8` linked flat (`cargo:rustc-link-arg-tests`) into the
   test binary of `crates/pcre2-link-test` (`publish = false`), which
   compiles and matches a regex through `pcre2` — ePHPm's scenario in
   miniature, on the three CI platforms (`windows.yml` runs it
   explicitly).
3. `cargo test --workspace`, clippy `-D warnings`, fmt; all harnesses 0
   diff (the engine is now the vendored 10.46 on every platform).
4. Windows CI (MSVC) green; the release binaries of macOS and Linux no
   longer need a system `libpcre2-8` (`otool -L` / `readelf -d` in the
   release job).
5. Docs: README (Embedding: the duplicate-symbol case and what vivacity
   does about it — and that the prefix removes vivacity's contribution
   to the conflict, not another crate's `pcre2-sys`), NOTICE (PCRE2
   BSD-3-Clause + sljit BSD-2, pcre2 / pcre2-sys Unlicense OR MIT, our
   forks), HANDOVER, DECISIONS, CHANGELOG (incl. the release binaries no
   longer needing a system libpcre2-8), CONTRIBUTING (six crates
   published), the two crate READMEs, this plan.

## 3. Meta-analysis

Fresh subagent, 2026-09-17, with real experiments (the library compiled
with the patch, link tests, a cargo workspace on stable 1.95). Eleven
findings, all folded into §2:

1. **The `PCRE2_SUFFIX` patch as written does not compile** (major):
   `pcre2.h` defines the macro twice — line 871 for the three-width
   generation and line 1053 for application use (the one every `.c` and
   `pcre2_internal.h:2084+` see) — both must be patched; and
   `PCRE2_UCHAR` / `PCRE2_SPTR` go through the same macro while their
   typedefs are literal `PCRE2_UCHAR8` / `PCRE2_SPTR8` → a
   `PCRE2_TYPE_SUFFIX` without prefix for the two types. Without
   `PCRE2_SYMBOL_PREFIX` the 137 exported symbols are byte-identical to
   the base (still upstreamable).
2. **Six width-independent symbols escape the macro** (major):
   `_pcre2_ckd_smul` (`pcre2_chkdint.c:66`), `_pcre2_utf8_table1..4`,
   `_pcre2_utf8_table1_size` (`pcre2_tables.c:100-114`) — PHP bundles
   them too. Ten lines in `pcre2_internal.h` after `PRIV`. Result:
   137/137 prefixed, `nm -u` = libc only.
3. **The current release binaries link a system PCRE2 dynamically**
   (major): `otool -L` on the v0.10.0 macOS arm64 binary →
   `/opt/homebrew/opt/pcre2/lib/libpcre2-8.0.dylib` (a Mac without
   Homebrew pcre2 cannot start it); Linux x86_64 → `NEEDED
   libpcre2-8.so.0`. Always-static fixes a user-visible bug — CHANGELOG —
   and changes the engine the harness exercises on those two platforms
   (system 10.4x → vendored 10.46): the harness is re-proven.
4. **The link test as designed proves nothing** (major): a static
   archive member nothing references is never pulled. Design that fails
   without the prefix and passes with it on the three platforms: the
   dummy object linked flat through `cargo:rustc-link-arg-tests`, dummies
   `pcre2_compile_8` and `_pcre2_check_escape_8` (in `pcre2_compile.o`,
   always pulled by `pcre2_code_free_8` from `Drop`) plus `pcre2_match_8`
   as a runtime second net; in a `publish = false` member
   `crates/pcre2-link-test`; `windows.yml` runs it explicitly (it only
   runs `--lib` tests today).
5. **Clippy and fmt gates go red** with the forks as members (major):
   3 + 30 clippy errors, 43 rustfmt diffs → `[lints.clippy] all =
   "allow"` in both forks, their upstream `rustfmt.toml` copied, their
   own `edition = "2024"`.
6. `bindings.rs` holds 74 × 3 widths, not 222 `_8`: prefix
   `pcre2_(\w+)_(8|16|32)` uniformly.
7. `upstream/LICENCE` does not exist in the crate: add PCRE2 10.46's
   (BSD-3 Cambridge + sljit BSD-2); NOTICE.md never mentioned PCRE2 —
   a pre-existing gap the binaries' BSD clause 2 required closing.
8. No `deny.toml` in the repo: criterion dropped.
9. Forks versioned with the workspace (0.12.0), upstream base in the
   description — publishing is `cargo publish --workspace` with one
   version.
10. Archive named `vivacity_pcre2` (`rustc-link-lib=static=vivacity_pcre2`).
11. `[lib] name = "pcre2"` is needed for the fork's seven doctests; two
    libs named `pcre2` in one graph compile and run (distinct metadata).

Verified correct by the reviewer: the macro pasting
(`vivacity__pcre2_check_escape_8`, `vivacity_pcre2_compile_8`,
`_pcre2_posix_class_maps8` covered), no literal `_8` names, sljit static,
`#[link_name]` mangling on macOS/MSVC, the renamed workspace dependency,
nothing in CI relying on `PCRE2_SYS_STATIC`, `.crate` size 772 KB,
alternatives (objcopy prefixes undefined symbols too and has no MSVC
equivalent; `-fvisibility=hidden` is irrelevant to static linking).
