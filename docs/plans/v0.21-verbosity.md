# `-q` et `-v` comme Composer — plan

> Suite de la PR de Luther (options globales `-n`/`-q`/`-v`/`--no-ansi` sur les
> cinq commandes, `ephpm/vivace` → `global-compat-flags`, 7fd67d3). Sa PR les
> rend acceptées ; elles restent sans effet. Or la sortie d'erreur fait partie
> du contrat : sous `-q` ou `-v`, vivacity affiche autre chose que Composer.
> Niveau 2 : rien d'irréversible, mais chaque ligne que vivacity écrit est
> touchée — le blast radius est la sortie entière.

## Ce que fait Composer 2.10.3 (mesuré le 2026-10-14, fixture laravel)

| commande | normal | `-q` | `-v` | `-vv` | `-vvv` |
|---|---|---|---|---|---|
| `install` (lock, cache chaud) | 115 lignes stderr | **0** | 117 | 226 | 585 |
| `update --no-install --dry-run` | 45 + 1 stdout | **0 + 0** | 50 | — | — |
| `remove … --no-install --dry-run` | 9 + 2 stdout | **0 + 0** | 14 | — | — |
| `dump-autoload` (`-o` aussi) | 0 + 2 stdout | **0 + 0** | 0 + 2 | — | — |
| `install` sans composer.json | 2, exit 1 | **0, exit 1** | 2, exit 1 | — | — |

**`-q` : rien, sur aucun des deux flux — y compris le message d'erreur**, code de
sortie inchangé. (`ConsoleIO` : `QUIET` → `VERBOSITY_QUIET`, toute écriture au
niveau normal tombe.)

**`-v` : les écritures `IOInterface::VERBOSE` de la source** (inventaire complet
par grep du phar ; celles qui concernent vivacity) :

| source | ligne | où |
|---|---|---|
| `Solver.php:231` | `Dependency resolution completed in %.3f seconds` | après chaque résolution : une à l'install depuis le lock, deux sur un update (résolution + extraction des paquets dev) |
| `Installer.php:560-561` | `Analyzed N packages to resolve dependencies` / `Analyzed N rules to resolve dependencies` | update : `count($pool)` après optimisation, `getRuleSetSize()` |
| `Installer.php:620-626` | `Installs: a:1.0, …` / `Updates: …` / `Removals: …` | update, après « Lock file operations » |
| `Installer.php:864-870` | idem | install, après « Package operations » |
| `Problem.php` (`$isVerbose`) | explication d'un ensemble insoluble plus détaillée | notre port l'a déjà (`problem.rs`, `is_verbose`), câblé à `false` |
| `ArtifactRepository.php:87,92` | `Found package … in file …` / `File … doesn't seem to hold a package` | dépôts `artifact` (vivacity les lit depuis 0.19) |
| `Installer.php:472` | la classe de l'exception d'un audit échoué | audit : vivacity ne l'exécute pas |
| `EventDispatcher.php:230,234,624` | lignes des listeners | scripts : rendus à `composer run-script`, qui reçoit l'option |

**`-vv` / `-vvv`** : requêtes HTTP, lectures de fichiers, timings internes —
226 et 585 lignes. Hors de portée d'une reproduction à l'octet.

## Décisions

1. **`-q` : vivacity n'écrit plus rien, ni stdout ni stderr, erreurs comprises.**
   Le code de sortie reste le contrat. Exception assumée : une panique Rust
   (bug) s'affiche quand même — ce n'est pas une sortie de Composer.
2. **`-v` : les lignes ci-dessus, à leur place exacte.** La durée est la nôtre,
   formatée `%.3f` ; le harness la normalise (chiffres → `N`), comme il le fait
   déjà pour les durées du dump. Les compteurs `Analyzed` sont une preuve de
   plus que le pool et le jeu de règles sont ceux de Composer : s'ils
   diffèrent, c'est un écart du port à corriger, pas à masquer.
3. **`-vv` et `-vvv` : la commande est rendue à Composer** (fallback, ou exit 3
   sous `--no-fallback`), comme tout ce que vivacity ne sait pas reproduire.
   Alternative écartée : traiter `-vv` comme `-v` — ce serait afficher autre
   chose que Composer en le sachant.
4. **Le fallback et `--run-scripts` transmettent l'option** : Composer reçoit
   les mêmes arguments (déjà vrai pour le fallback, qui rejoue `ARGV` — à
   vérifier) ; `composer run-script` reçoit `-q`/`-v`.
5. **Mécanique : un niveau de verbosité par exécution, pas un descripteur
   redirigé.** Rediriger le fd 2 couperait aussi le stderr de PHP chez ePHPm,
   qui embarque `vivacity::run` dans son processus. Un module
   `vivacity_core::io` porte le niveau (atomique, posé au début de `run`,
   remis à normal à la fin, y compris sur erreur) et deux macros,
   `say!` (normal) et `say_verbose!` ; les ~130 `eprintln!`/`println!` des
   quatre crates passent par elles. Limite documentée : deux `run` concurrents
   dans un même processus partagent le niveau.

## Fichiers, dans l'ordre

1. `crates/vivacity-core/src/io.rs` (nouveau) : `Verbosity`, `set`, `get`,
   garde RAII qui restaure, macros. Tests unitaires.
2. Remplacement mécanique `eprintln!`/`eprint!`/`println!` → macros dans
   `vivacity`, `vivacity-core`, `vivacity-resolver`, `vivacity-autoload`
   (hors tests). Vérifié par grep : plus aucun `eprint` hors `io.rs` et tests.
3. `lib.rs` : la verbosité tirée des arguments (`GlobalCompatArgs` et les
   champs de `require`/`remove`), posée dans `run` ; `-vv`+ → fallback.
   L'erreur finale (`Error: …`) passe aussi par la macro.
4. Lignes `-v` : `vivacity-resolver` (durée de chaque `solve`, `Analyzed`) et
   `vivacity` (`Installs:`/`Updates:`/`Removals:` dans `install.rs` et
   `update.rs`), `is_verbose` câblé dans `session.rs`, lignes du dépôt
   artifact.
5. `scripts.rs` : `-q`/`-v` transmis à `composer run-script`.
6. Les commentaires de doc de 7fd67d3 dont le texte entre backticks a été
   perdu (`GlobalCompatArgs`, `DumpArgs::no_scripts`) : rétablis.
7. `harness/verbosity.sh` (nouveau, en CI) : scénarios × {`-q`, `-v`},
   Composer contre vivacity, **stdout et stderr entiers** (pas d'ancre : sous
   `-q` il n'y en a pas), code de sortie, durées normalisées. Scénarios :
   install laravel (froid, chaud, no-op), install sans composer.json,
   install avec lock périmé, update `--no-install` (instantané figé),
   update insoluble (fixture `solver-problems`, explication verbeuse),
   remove, require, dump-autoload et `-o`, dépôt artifact, `-vv` → ligne
   « delegating to ».
8. Docs : CHANGELOG, DECISIONS, README (options), HANDOVER, ce plan.

## Vérification

`cargo fmt --check`, clippy `-D warnings` macOS + `x86_64-pc-windows-gnu`,
suite complète, `harness/verbosity.sh` vert, et le balayage de tous les
harnais (la sortie normale ne doit pas bouger d'un octet).

## Méta-analyse (sous-agent frais, 2026-10-15) — et ce qui change

Onze points, un bloquant et cinq majeurs, tous mesurés ou lus dans la source.
Le plan ci-dessus est **amendé** par ce qui suit ; là où ils divergent, cette
section l'emporte.

**1. Bloquant — `-q` ne fait pas taire les erreurs de Composer.** La mesure
généralisait un seul cas (composer.json absent, écrit au niveau normal). Le gros
des erreurs est au niveau QUIET : `Installer.php:508, 548, 551, 730, 775, 818,
826` (« Your requirements could not be resolved… », l'avertissement
`--no-dev`, « Warning: The lock file is not up to date… », « Your lock file
cannot be installed… », « …does not contain a compatible set… ») et tous les
encadrés d'exception de Symfony (`Application::doRenderThrowable`, écrits à
`VERBOSITY_QUIET`). Mesuré : update insoluble `-q` → la ligne de tête, exit 2 ;
lock périmé `install -q` → l'avertissement, exit 0 ; JSON invalide, transport
→ l'encadré, exits 1 et 100. **Décision 1 remplacée :** trois niveaux d'écriture
— `quiet` (toujours affiché), `normal`, `verbose` — et chaque site classé selon
son équivalent Composer. vivacity concatène aujourd'hui tête (QUIET) +
problèmes (normal) + avertissement `--no-dev` (QUIET) en une chaîne
(`session.rs:1021-1032`, imprimée `update.rs:389`) : à scinder. La ligne finale
`Error: …` reste QUIET.

**2. Majeur — le fallback ne rejoue pas l'argv d'`install`.** `fallback_or_fail`
reconstruit `composer install` à partir de quelques drapeaux (perd `-q`/`-v`,
`--dry-run`, `--prefer-*`, `--apcu*`, `--no-blocking`) et fait `exec()` sous
unix — chez ePHPm, remplacer le processus hôte. `dump-autoload` n'a pas de
fallback (exit 3). `delegate_resolution` rejoue bien l'argv d'origine.
**Changement :** `-vv`/`-vvv` délègue par une fonction unique pour les cinq
commandes, appelée en tête de `run` avant toute lecture : argv d'origine moins
les drapeaux propres à vivacity (`--run-scripts` → pas de `--no-scripts`,
`--check-scope`, `--no-fallback`), en processus fils (jamais `exec`). La
remise à plat de `fallback_or_fail` sur ce modèle est **notée, hors périmètre**
(elle change le comportement du fallback d'`install` pour tous).

**3. Majeur — la durée de résolution ne s'imprime pas dans `solve`.** À
l'install, vivacity ne résout pas : la transaction vient du lock. La ligne est
émise par `install.rs` à la place de Composer (après l'avertissement de lock
périmé et la vérification des exigences, avant « Package operations »), jamais
sur le retour anticipé ni dans l'install qui suit un update. À l'update, l'ordre
mesuré est : completed, Analyzed ×2, « Nothing to modify in lock file »,
completed, « Writing lock file » — or vivacity imprime « Nothing to modify »
après les deux résolutions. **Changement :** la session renvoie ses événements
dans l'ordre (ou imprime « Analyzed… » et « Nothing to modify » entre `solve` et
`extract_dev_packages`) ; sur échec, « completed » précède l'erreur, sans les
« Analyzed ».

**4. Majeur — l'inventaire `-v` ignorait les plugins émulés et `require`.**
`VersionSelector.php:160` (avertissements « Cannot use … » répétés, VERBOSE —
`require.rs:265` les filtre déjà par `!w.verbose`) ; dealerdirect
(`Plugin.php:184-217, 310, 338`, sur stdout, y compris la sortie de
`phpcs --config-set`) ; symfony/flex (`AbstractConfigurator::write`,
`AddLinesConfigurator.php:109, 204`, `ScriptExecutor.php:56-61`). Les dépôts
`artifact` ne sont pas concernés (`update` les refuse ; l'install depuis le
lock n'imprime pas « Found package »). **Changement :** sous `-v`, délégation
quand dealerdirect ou Flex est actif ; `require` imprime ses avertissements
verbeux ; artifact retiré du plan. *(Depuis le 2026-10-22,
`docs/plans/verbose-plugins.md` : la règle devient « plugin dont les lignes
`-v` ne sont pas reproduites » — les lignes `>` des écouteurs sont émises
pour dix plugins (cinq autres, sans écouteur, restent muets), Flex et dealerdirect restent rendus.)*

**5. Majeur — comparer stdout + stderr entiers échoue hors verbosité.** Écarts
connus en mode normal : ligne `vivacity: N installed …` et lignes `Note:`,
`dump-autoload` (Composer : « Generating autoload files » / « Generated
autoload files » sur stdout ; vivacity : `vivacity: autoloader generated …`
sur stderr — le compte de classes concorde), avertissement de root-version,
lignes « Downloading » selon le cache, barre de progression (sans
`--no-progress` et sans `CI` ; sous `-v` elle ajoute le temps écoulé), audit
sur stdout. Aucune normalisation de durée n'existe aujourd'hui (le plan disait
le contraire, à tort). **Changement :** harnais avec `--no-progress`, `CI=1`,
`--no-audit`, `COMPOSER_ROOT_VERSION` (l'avertissement de root-version n'est
plus un écart depuis le 2026-10-16 — commit « Print Composer's root-version
warning before a command's first line », `docs/plans/root-version-warning.md` ;
la variable reste posée pour les autres cas, retirée par `@unset:` dans les
siens), caches vides séparés pour le cas froid ;
lignes `^vivacity: ` et `^Note: ` tolérées comme dans `steps.sh` ;
`in [0-9]+\.[0-9]{3} seconds` normalisé ; encadrés d'exception : code de sortie
seulement sous `-v` (classe et pile avec chemins du phar). Les lignes de dump
de Composer sur stdout : à aligner dans ce chantier (peu cher), sinon dump hors
comparaison.

**6. Majeur — le calcul de la verbosité est celui de Symfony, pas de clap.**
Mesuré : `-v -v` = `-v` chez Composer (clap compte 2) ; `-q -vvv` = quiet ;
`SHELL_VERBOSITY` (-1 → quiet, 1 → verbose) ; `vivacity -q install` (option
avant la commande) exit 2 ; `--verbose=1` refusé. **Changement :** niveau
calculé comme `Application::configureIO` — `SHELL_VERBOSITY`, puis `-q`, puis
les jetons exacts `-vvv`/`-vv`/`-v` de l'argv.

**Mineurs.** (7) Atomique de processus : le bon choix (un thread-local raterait
le thread de politique d'`install.rs:175`) ; remise à « normal » en fin de run
plutôt que restauration ; les macros passent par `eprintln!`/`println!` (capture
de cargo test) ; tests de `io.rs` en un seul `#[test]` ; même limite documentée
que `ARGV`. (8) `tests/embed.rs` attend exit 1 pour `-vvv` partout — à revoir ;
l'entrée CHANGELOG de 7fd67d3 (« same narrative at every verbosity ») à
réécrire. (9) Niveaux de vivacity elle-même : raisons d'exit 3 et
`--check-scope` en QUIET, « delegating to » en normal, `VIVACITY_TRACE`
toujours. (10) `Installs:`/`Updates:` d'update dans l'ordre brut de la
transaction (avant le tri alphabétique, `Installer.php:600-627` vs `649`),
version jolie complète (référence d'une version dev) — un cas dev au harnais.
(11) Harnais et table de classement des sites **avant** les ~130 remplacements.

**Vérifié juste par la méta :** comptes `Analyzed` identiques à Composer
(laravel 767/4487, symfony 952/6778, drupal 385/1652, 3 petits projets) ;
explications verbeuses déjà portées : 10 cas `solver-problems` identiques à
l'octet sous `-v` une fois `is_verbose` câblé ; nombre de résolutions par
commande juste ; pas d'autre ligne `-v` sur install froid, require, remove,
update, dump `-o` (avec `--no-progress`) ; `delegate_resolution` rejoue argv.

## Revue indépendante (sous-agent frais, 2026-10-15) — et ce qui a changé

Dix points, un bloquant, trois majeurs. Tous repris avant le commit.

**Bloquant — `-v` avec n'importe quel plugin.** Composer écrit une ligne par
écouteur de plugin qu'il dispatche (`EventDispatcher.php:230`,
`> post-autoload-dump: Classe->méthode`), et les plugins émulés journalisent
par-dessus (bamarni `Logger.php:34`, composer-merge-plugin `Logger.php:68`).
Mesuré sur `fixtures/projects/bin-plugin` : deux lignes manquaient côté
vivacity. La règle « Flex ou dealerdirect » devient « tout plugin actif
(installé ou verrouillé, et autorisé) → délégation sous `-v` ». *(Resserrée
le 2026-10-22 : `docs/plans/verbose-plugins.md`.)*

**Majeurs.** (2) Le fallback d'`install` reconstruit sa ligne et ignorait
`-q`/`-v` : tout processus Composer lancé par vivacity reçoit maintenant
`SHELL_VERBOSITY` (ce que Symfony exporte lui-même). (3) Les raisons d'une
délégation sortaient sous `-q` : au niveau normal quand Composer prend la
main, QUIET quand la commande s'arrête en 3. (4) Régression au niveau normal :
« Nothing to modify in lock file » sortait avant `validate_package`, là où
Composer valide dans `Solver::solve` — l'ordre est rétabli.

**Mineurs.** (5) Les lignes d'après-résolution sont retenues par la session
(`SolveReport::events`) et écrites par la commande après ses vérifications
Flex, sinon une délégation les faisait sortir deux fois ; sur les chemins
d'erreur la session les écrit elle-même avant de rendre l'erreur.
(6) `--no-autoloader` n'existe pas sur le `require`/`remove` de Composer :
filtré des deux délégations. (7) `--check-scope` répond nativement quelle que
soit la verbosité. (8) `update` vérifie `COMPOSER=` avant l'absence du
manifeste, comme les autres commandes. (9) Harnais : même régime de plugins
des deux côtés, un cas `-vv`, un cas plugins actifs (symfony), filtre des
lignes `vivacity:` sur stderr seulement et jamais sous `-q`. (10)
`SHELL_VERBOSITY="1e1"` : le cast PHP lit 10 (normal), le nôtre lisait 1.

Vérifié juste par la revue : le calcul du niveau (préfixes, `--`, `-nv`,
`-qn`), les niveaux de chaque site, l'ordre des lignes `-v`, les lignes de
dump, le message de manifeste absent, la mécanique de délégation, l'absence
de concurrence entre tests sur le niveau global.

## Résultat (2026-10-15)

Livré sur la branche `quiet-verbose`, posée sur la PR #7 de Luther.
`harness/verbosity.sh` : 23 scénarios, 67 cas, tous identiques à Composer
2.10.3 (stdout, stderr, code de sortie) ; suite complète et tous les harnais
verts (la sortie normale n'a pas bougé). Hors périmètre, noté : la remise à
plat de `fallback_or_fail` sur le modèle de `delegate_for_verbosity` (argv
d'origine, processus fils) ; l'émission des lignes d'écouteurs à leur place,
qui rendrait `-v` natif avec les plugins.
