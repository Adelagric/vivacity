# v0.12 — Pure-Rust dist extraction: the rest of the libphp symbol chain

Started 2026-09-16. Follow-up to v0.12-pcre2-prefix.md — same embedder, next
libraries.

## 1. Scope

### Problem

With PCRE2 prefixed (0.11.0), ePHPm's PHP-linked binary still fails at link:

```
rust-lld: error: duplicate symbol: BZ2_bzDecompress
>>> defined at decompress.c … bzip2-sys …
>>> defined at libbz2.a … (libphp's bundled bzip2)
```

The zip crate's default features pull three C libraries whose exports are
the plain C API names: `bzip2-sys` (33 `BZ2_*`), `lzma-sys` via `xz2`
(219 `lzma_*`), `zstd-sys` (294 `ZSTD_*`). What PHP bundles, measured with
`llvm-nm --defined-only` on the php-sdk 8.5.7 archives an embedder links:

| Library | Linux SDK (`lib*.a`)  | Windows SDK (`php8embed.lib`) |
|---------|-----------------------|-------------------------------|
| bzip2   | `libbz2.a`, 33 `BZ2_*` | bundled, 33 `BZ2_*`          |
| zlib    | `libz.a`, 86 globals   | bundled, 41 `inflate*`/`deflate*` |
| lzma    | `liblzma.a`, 219 `lzma_*` | not present               |
| zstd    | not present            | bundled, 294 `ZSTD_*`        |

Every overlap is a duplicate-symbol error on that platform. vivacity's own
code never touches these crates: all three arrive through `zip`'s default
features, and vivacity only ever *decompresses* zip dists (a Composer
registry produces store and deflate entries).

### Decision, per library

| Library | Was | Now | Why |
|---------|-----|-----|-----|
| zlib / deflate | flate2 Rust backend (miniz_oxide/zlib-rs), no `libz-sys` | unchanged | already pure Rust, no exported C symbols |
| bzip2 | `bzip2-sys` (C) | `libbz2-rs-sys`, the bzip2 crate's pure-Rust backend | keeps bzip2 zip entries working; its exports carry the `LIBBZ2_RS_SYS_v…` semver prefix, and the backend feature sets `bzip2-sys/__disabled`, whose build script then compiles nothing — additive-feature-safe even though zip still names bzip2's default |
| LZMA (zip method 14) | `lzma-rs` (pure Rust) via zip's `lzma` feature | unchanged | already pure Rust |
| xz (zip method 95) | `xz2` → `lzma-sys` (C) | dropped | no pure-Rust backend in zip 2.4.2; no Composer dist has ever used it; a hit is refused with zip's unsupported-method error rather than linked as colliding C |
| zstd (zip method 93) | `zstd` → `zstd-sys` (C) | dropped | same as xz — zip 2.4.2 has no ruzstd backend, and prefix-vendoring 294 symbols for a method registries never emit is not worth carrying |

The mechanism is two Cargo.toml lines: `zip` with `default-features =
false` and the six features that remain (`aes-crypto`, `bzip2`, `deflate`,
`deflate64`, `lzma`, `time`), plus a feature-only direct dependency on
`bzip2` selecting `libbz2-rs-sys`. Cargo unions features across the tree,
so the backend flip holds no matter who else names `bzip2`.

Prefix-vendoring (the PCRE2 pattern) was considered for all three and kept
as the fallback: it is only *needed* when the code path is exercised and no
pure-Rust implementation fits. None of the three met that bar — bzip2 has a
first-party pure-Rust backend that is already prefix-aware, and xz/zstd
have no traffic to serve.

## 2. Proof

- **Link**: ePHPm's PHP-linked release build (`php8embed.lib`, whole-archive
  static deps) with vivacity patched to this branch links with zero
  duplicate symbols; unpatched 0.11.0 reproduces the `BZ2_*`/`ZSTD_*`
  duplicates. Linux holds by subtraction: `lzma-sys` and `zstd-sys` are out
  of the graph entirely, `bzip2-sys` compiles nothing.
- **Parity**: decompression must be byte-identical, and
  `harness/diff-vendor.sh` (six fixtures, with and without autoloader) is
  the guard that the pure-Rust decoders produced identical `vendor/` bytes:
  0 diff.
- **Regression pin**: `tools/check-clib-deps.sh` in CI — no
  lzma-sys/zstd-sys/libz-sys/xz2/zstd in `cargo tree`, `bzip2-sys` resolves
  with `__disabled` only, `libbz2-rs-sys` carries `semver-prefix`.
