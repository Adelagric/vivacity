# v0.17 — `tar` dists (asset-packagist)

## 1. Scope

### Problem
The corpus (2026-09-19) hands 8 entries to Composer for "no usable dist".
Read in the locks, that is not one problem but three: **263 packages with
`dist.type: tar`** (asset-packagist → `registry.npmjs.org/….tgz`: elgg 186,
humhub 54, friendica 23), 3 git-only packages (one each in ampache,
friendica, kovah-linkace), and `path` sources absent from the fixture
(drupal — blocked by the GPL scaffold anyway). "vcs" was the wrong name for
the first blocker. This plan is the tar downloader only.

### Reference (Composer 2.10.3, read in the phar)
`TarDownloader::extract` = `new \PharData($file); extractTo($path, null,
true)`; `ArchiveDownloader::install` on top (identical to
docs/reference/ArchiveDownloader.php: temp dir, single top-level directory
moved up, `.DS_Store` rule). Cache key `files/<name>/<sha1(url)>.tar`.

### Oracle facts (PharData, PHP 8.5.10, umask 022 — measured 2026-09-22)
- file entries: the **exact header mode** (0666, 0664, 0755 kept, no umask);
- directory entries: mode **ignored** → 0777 & ~umask; implicit parents the
  same (npm tgz have no directory entries at all);
- symlink and hard-link entries: an **empty regular file** with the header
  mode (no link is created — no escape possible);
- pax long names handled; `a/../b` is normalised lexically inside the
  archive by PharData (vivacity refuses `..`, stricter, documented).
Composer install on npm-asset/{bail,after,blob,animate.css,color-name}:
every file mode equals the tar header, directories 0755, `package/` (or
`v1.1/`) stripped.

### Non-goals
Git-only packages (`GitDownloader`, own plan — the `.git/` content is not
byte-deterministic, the parity contract itself needs a decision);
`yiisoft/yii2-composer` (own step, unblocks humhub with this one);
`oomphinc/composer-installers-extender` (layout plugin, friendica stays).

### Success criteria
1. `harness/diff-vendor.sh`-style check on a fixture with tar dists:
   vendor/ identical (modes and contents) to Composer, install + no-op +
   `--no-dev`, on Linux and macOS in CI; Windows: modes not compared,
   contents are.
2. Corpus: elgg native 0 diff (+1 both modes); humhub still fallback
   (yii2-composer) but no tar reason left.
3. `--check-scope` no longer lists tar packages; git-only reason reworded
   ("no zip or tar dist, no path source").

## 2. Plan
1. `Cargo.toml`: `tar` crate pinned (pure Rust, no C; flate2 already in
   the tree via zip). DECISIONS entry for the dependency.
2. `vivacity-core/src/extract.rs`: `extract_tar(bytes, dest)` — gzip
   (flate2) + `tar::Archive`, entries walked once into a `Vec` (root_strip
   needs the whole list first): the same `entry_path` rule (no `..`, no
   absolute), `root_strip` shared with zip through a small
   `(path, is_dir)` list, then per entry: dir → `ensure_dir` (mode
   ignored); file → write + `set_permissions(header mode & 0o7777)` on
   unix; symlink/hardlink → empty file + header mode; other types
   (char/block/fifo) → hostile. `MAX_UNCOMPRESSED` on the sum of sizes.
3. `store.rs`: `ensure(..., bytes, kind)` with `DistKind::{Zip, Tar}`;
   store key when the dist has no reference: `sha1(url)[..12]` instead of
   `noref` (two URLs for one version must not share an entry).
4. `fetch.rs`: cache file extension from the dist type (`.tar`).
5. `installer.rs`: pass the dist type; `scope.rs`: accept `tar`, reword
   the reason.
6. Fixture `fixtures/projects/tar-dist` (asset-packagist, 5 packages with
   the measured mode variety + one zip) with a committed lock; the dists
   must come from the network (asset-packagist is not in our registry
   snapshots — `fixtures/make.sh` already downloads for other fixtures:
   check) — harness `harness/tar-dist.sh`: install, no-op, `--no-dev`,
   `dump-autoload -o`, `compare_vendor` (modes included). In ci.yml.
7. Corpus rerun on elgg, humhub, friendica; report; docs.

## 3. Meta-analysis (adversarial, self)
- **Modes are the whole risk.** PHP's chmod is exact; `std::fs::write`
  then `set_permissions(mode)` gives the same result whatever the umask.
  Windows: no modes, nothing to do. macOS/Linux compared by `compare.sh`
  (it inventories modes): the harness is the proof, not this reading.
- **Directory mode "ignored"** was measured on one explicit 0700 entry.
  Could a 0777 entry come out 0777? No: mkdir(0777 & ~umask) — but if the
  measurement is wrong the harness on a crafted tar will say so. Add such
  an entry to the fixture? The fixture's dists come from npm (no dir
  entries): a unit test on a crafted tar covers the rule, the oracle test
  (`tests/oracle_*`) can run PharData through `php -r` — do that.
- **Symlink → empty file** looks like a PHP bug, and it is; parity means
  reproducing it. A future PHP might fix it → drift job territory. Note
  in DECISIONS.
- **Zip bomb / size**: tar sizes come from headers; a lying header is
  caught by the read (we read `size` bytes). Sum checked like zip.
- **Store key change** (`noref` → sha1) changes nothing for zip (they all
  have a reference) and only touches new tar entries: no migration.
- **The gain is small in the corpus (+1)** but the Yii ecosystem is built
  on asset-packagist; the honest claim is "tar dists install", not
  "+N entries".
- **Cache parity**: Composer keeps `<sha1>.tar`; if we wrote `.zip` the
  two tools would refetch each other's files. Covered by step 4 and the
  no-op timing in the harness (second install must not download).
