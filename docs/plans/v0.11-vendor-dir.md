# v0.11 — `config.vendor-dir` and `config.bin-dir`

Started 2026-09-16. Level 1 (multi-file, reversible) with the project's
practice of a fresh-subagent meta-analysis.

## 1. Scope

### Problem

18 of the 105 corpus projects set `config.vendor-dir` and/or
`config.bin-dir` (`lib/vendor`, `Packages/Libraries`, `src/vendor`,
`upload/system/storage/vendor/`, `./vendor/composer/vendor`, `bin`, `bin/`…);
two of them spell the defaults (`vendor`, `vendor/bin`). In
`docs/corpus/2026-09-16.md` the reason ranks first (10 + 6 occurrences),
but it is the *sole* reason for only about five entries in dev mode
(forkcms, joomla-cms, opencart, phpdocumentor, yourls) and seven in
no-dev (+ nextcloud-server, wallabag); the others also carry a plugin
vivacity does not emulate. The expected gain is therefore ~5 / ~7
entries, and the removal of the first-ranked reason for the rest.
vivacity hard-codes `vendor/` in the layout, the installer, the autoload
generator, the bin proxies, the state files and the plugin emulations. It
is the largest fallback reason of the corpus (`docs/corpus/2026-09-16.md`)
and the cheapest: a configuration value, no new semantics.

### Reference (Composer 2.10.3)

- `Config::get('vendor-dir' | 'bin-dir')`: `COMPOSER_VENDOR_DIR` /
  `COMPOSER_BIN_DIR` environment first, else the config value (project
  `config`, then the global config, defaults `vendor` and
  `{$vendor-dir}/bin`); `{$key}` placeholders substituted recursively
  (`process`), the result `rtrim`med of `/` and `\`, `~/` and `$VAR` /
  `%VAR%` prefixes expanded (`Platform::expandPath`), then made absolute
  against the project directory **without canonicalisation**
  (`Config::realpath`: a path matching `^(/|[a-z]:|[a-z0-9.]+://|\\\\)`
  is kept as is, otherwise `baseDir . '/' . path`).
- `LibraryInstaller`: `vendorDir = rtrim(get('vendor-dir'), '/')`,
  `realpath`ed once the directory exists; a package's install path is
  `vendorDir/<pretty name>` (+ `target-dir`). `BinaryInstaller`: links in
  `binDir` (`realpath`ed after `ensureDirectoryExists`); proxies computed
  from the link's directory to the binary and to
  `<vendorDir>/autoload.php` with `findShortestPathCode`; the bin
  directory is removed when it ends up empty after a removal.
- `AutoloadGenerator`: `vendorPath = realpath(realpath(get('vendor-dir')))`,
  `targetDir = vendorPath/composer`, `$vendorDir` code =
  `findShortestPathCode(targetDir, vendorPath)` (`dirname(__DIR__)`),
  `$baseDir` code = `findShortestPathCode(vendorPath, basePath)` with
  `__DIR__` → `$vendorDir` (`dirname(dirname($vendorDir))` for
  `lib/vendor`, `Filesystem::findShortestPathCode` repeats `dirname(`);
  `vendorPath/` is excluded from the classmap scan of any directory that
  contains it (line 353); `InstalledVersions` mapped at
  `vendorPath/composer/InstalledVersions.php`.
- `installed.json` / `installed.php`: paths relative to
  `vendorPath/composer` (`findShortestPath`, absolute when no shorter);
  the root package's `install_path` too (`'/../../'` today in `state.rs`,
  `'/../../../'` for `lib/vendor`).
- `BinaryInstaller::installBinaries`: an existing `link` that is not a
  symlink is *skipped* with `Skipped installation of bin X for package Y:
  name conflicts with an existing file` (silent in the
  `ensureBinariesPresence` pass); `removeBinaries` unlinks only the
  removed package's own bins and `rmdir`s the bin directory when it ends
  up empty. The phpunit special case compares against the non-canonical
  `vendorDir` string.
- `Locker::getContentHash` ignores `config`: changing `vendor-dir` or
  `bin-dir` on a fixture keeps its lock valid — the harness can stage the
  existing fixtures with variants.

### Constraints

- Byte-identical output stays the promise: whole-project comparison
  (`harness/lib/compare.sh`), autoload files included, `dump-autoload -o`
  included.
- Every emulated plugin and generated file that lives in `vendor/`
  (runtime stub, `pest-plugins.json`, `CodeSniffer.conf`,
  `GeneratedConfig.php`, `installed.json`, `installed.php`,
  `platform_check.php`, bin proxies) follows the directory.
- Windows: absolute install paths from the canonical vendor directory as
  today; the `.bat` proxies relative to the bin directory.
- Store hardlinks: nothing new is written in place (memory rule).
- No new crate dependency.

### Non-goals

- `vendor-dir` / `bin-dir` values the harness cannot cover stay scope
  issues (fallback to Composer, explained by `--check-scope`): absolute
  paths, `..`-prefixed paths, `.` (the project root itself), `~/`,
  `$VAR` / `%VAR%` prefixes, self-referencing placeholders. Composer
  handles them (`Platform::expandPath`, absolute `install-path` and
  `$baseDir` when the common path is `/`), but no corpus project uses
  them and shipping them untested contradicts the harness-proven promise.
  Only `{$vendor-dir}` / `{$bin-dir}` placeholders are honoured.
- `preferred-install: source` stays a scope issue.
- `bin-compat`, `bin-dir` on Windows symlink modes: unchanged.
- `composer/installers` `{$vendor}` placeholder is the package vendor
  name, not the directory: untouched.

## 2. Plan

## 3. Meta-analysis

Fresh subagent, 2026-09-16, twelve findings; all folded into §1–§2 above:

1. **bin-dir owned by the user** (major): vivacity overwrites an existing
   file with a proxy and `prune_orphan_bin_proxies` deletes any foreign
   file — Composer skips the conflicting bin with a message and only
   unlinks its own. Fixed in file 3; the symfony fixture's `bin/phpunit`
   and `bin/console` are the test.
2. **Vacuous pass through fallback** (major): the harness runs vivacity
   with `--no-fallback`.
3. **Root `install_path` hard-coded** in `state.rs` (major): file 4.
4. **Corpus numbers** (major): a partial re-run cannot feed the report
   (`results.jsonl` truncated); full re-run. The "16 entries for this
   reason alone" claim was wrong: ~5 dev / ~7 no-dev; §1 corrected.
5. **compare.sh tolerances keyed on `vendor/`** (major): `VENDOR_REL`.
6. **Staging model** (major): full fixture tree like `diff-vendor.sh`,
   not `stage_project`'s two files, or variants 2 and 3 test nothing.
7. **Untested forms** (`~`, `$VAR`, absolute, `..`, `.`): scope issues,
   not silent support; no recursion guard claim.
8. `dirname(dirname($vendorDir))`, not `dirname($vendorDir, 2)`.
9. Windows: the harness added to `windows.yml`.
10. phpunit hack uses the non-canonical vendor path; bin dir `rmdir`
    after removal does not exist today — added.
11. `package_root` and the `customs` filter are code sites, listed.
12. Harness written first and proven to fail; removal/steps validation
    after step 4.

Verified correct by the reviewer: the `Config::get` semantics (env >
config, `rtrim`, `realpath` without canonicalisation, placeholders via
recursive `get`), `LibraryInstaller` / `BinaryInstaller` `realpath`s,
the autoload path codes and the exclusion condition (already ported),
`installed.*` paths relative to `realpath($repoDir)`, `config` excluded
from the content hash (except `config.platform`), `runtime_stub.rs`
deriving its nesting from the real vendor directory, the list of CLI
sites.
