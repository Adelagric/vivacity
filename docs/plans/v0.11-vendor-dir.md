# v0.11 — `config.vendor-dir` and `config.bin-dir`

Started 2026-09-16. Level 1 (multi-file, reversible) with the project's
practice of a fresh-subagent meta-analysis.

## 1. Scope

### Problem

18 of the 105 corpus projects set `config.vendor-dir` and/or
`config.bin-dir` (`lib/vendor`, `Packages/Libraries`, `src/vendor`,
`upload/system/storage/vendor/`, `./vendor/composer/vendor`, `bin`, `bin/`,
`{$vendor-dir}/bin`…); 16 of them are in the fallback bucket for that
reason alone (the other two spell the defaults: `vendor`, `vendor/bin`).
vivacity hard-codes `vendor/` in the layout, the installer, the autoload
generator, the bin proxies, the state files and the plugin emulations. It
is the largest fallback reason of the corpus (`docs/corpus/2026-09-16.md`)
and the cheapest: a configuration value, no new semantics.

### Reference (Composer 2.10.3)

- `Config::get('vendor-dir' | 'bin-dir')`: `COMPOSER_VENDOR_DIR` /
  `COMPOSER_BIN_DIR` environment first, else the config value (project
  `config`, then the global config, defaults `vendor` and
  `{$vendor-dir}/bin`); `{$key}` placeholders substituted recursively
  (`process`), the result `rtrim`med of `/` and `\`, `~/` and `$VAR` /
  `%VAR%` prefixes expanded (`Platform::expandPath`), then made absolute
  against the project directory **without canonicalisation**
  (`Config::realpath`: a path matching `^(/|[a-z]:|[a-z0-9.]+://|\\\\)`
  is kept as is, otherwise `baseDir . '/' . path`).
- `LibraryInstaller`: `vendorDir = rtrim(get('vendor-dir'), '/')`,
  `realpath`ed once the directory exists; a package's install path is
  `vendorDir/<pretty name>` (+ `target-dir`). `BinaryInstaller`: links in
  `binDir` (`realpath`ed after `ensureDirectoryExists`); proxies computed
  from the link's directory to the binary and to
  `<vendorDir>/autoload.php` with `findShortestPathCode`; the bin
  directory is removed when it ends up empty after a removal.
- `AutoloadGenerator`: `vendorPath = realpath(realpath(get('vendor-dir')))`,
  `targetDir = vendorPath/composer`, `$vendorDir` code =
  `findShortestPathCode(targetDir, vendorPath)` (`dirname(__DIR__)`),
  `$baseDir` code = `findShortestPathCode(vendorPath, basePath)` with
  `__DIR__` → `$vendorDir` (`dirname($vendorDir, 2)` for `lib/vendor`);
  `vendorPath/` is excluded from the classmap scan of any directory that
  contains it (line 353); `InstalledVersions` mapped at
  `vendorPath/composer/InstalledVersions.php`.
- `installed.json` / `installed.php`: paths relative to
  `vendorPath/composer` (`findShortestPath`, absolute when no shorter).
- `Locker::getContentHash` ignores `config`: changing `vendor-dir` or
  `bin-dir` on a fixture keeps its lock valid — the harness can stage the
  existing fixtures with variants.

### Constraints

- Byte-identical output stays the promise: whole-project comparison
  (`harness/lib/compare.sh`), autoload files included, `dump-autoload -o`
  included.
- Every emulated plugin and generated file that lives in `vendor/`
  (runtime stub, `pest-plugins.json`, `CodeSniffer.conf`,
  `GeneratedConfig.php`, `installed.json`, `installed.php`,
  `platform_check.php`, bin proxies) follows the directory.
- Windows: absolute install paths from the canonical vendor directory as
  today; the `.bat` proxies relative to the bin directory.
- Store hardlinks: nothing new is written in place (memory rule).
- No new crate dependency.

### Non-goals

- `vendor-dir` pointing outside the project (`../vendor`, absolute): the
  resolution supports it (Composer does), unit-tested, not in the harness
  (a foreign absolute path cannot be normalised in the comparison).
- `preferred-install: source` stays a scope issue.
- `bin-compat`, `bin-dir` on Windows symlink modes: unchanged.
- `composer/installers` `{$vendor}` placeholder is the package vendor
  name, not the directory: untouched.

   `COMPOSER_VENDOR_DIR=env-vendor` + `bin-dir: {$vendor-dir}/tools`), plus

## 2. Plan

### Files

1. `crates/vivacity-core/src/dirs.rs` (new): `Dirs { vendor: PathBuf,
   bin: PathBuf }` absolute like `Config::realpath`, plus `vendor_rel()` /
   `bin_rel()` (project-relative, normalised, `..` allowed) —
   `Dirs::resolve(project_dir, manifest) -> Result<Dirs>`: env >
   project `config` > global config > default; `{$vendor-dir}` /
   `{$bin-dir}` / `{$home}` substitution with a recursion guard; `~/`,
   `$VAR`, `%VAR%` expansion; `rtrim("/\\")`; Composer's absolute-path
   regex (`is_absolute_path` covers `/`, `x:`, `\\`; add `scheme://`).
   Unit tests: defaults, each source, precedence, placeholder, trailing
   slashes, `./` prefix, absolute, outside root.
2. `crates/vivacity-core/src/layout.rs`: `Layout` carries `dirs: Dirs`;
   `vendor_rel(name, target_dir)` prefixes `dirs.vendor_rel()`; every
   `"vendor/"` test (`inside vendor/` refusal, `abs`, `install_path`,
   removals, `installed_packages`, `has_state`) uses it; accessors
   `vendor_dir()`, `bin_dir()`, `composer_dir()`. `vendor_only` and
   `resolve` take the `Dirs` (resolved by the caller once). Tests adjusted
   + one with `lib/vendor`.
3. `crates/vivacity-core/src/binproxy.rs`: `install_binaries(vendor_dir,
   bin_dir, …)` and the removal path take the bin directory; the empty
   bin directory removed after a removal like `BinaryInstaller` (check
   what exists today first). Unit test with `bin_dir = <root>/bin`:
   `__DIR__ . '/../vendor/…'` in the proxy.
4. `crates/vivacity-core/src/installer.rs`, `state.rs`,
   `runtime_stub.rs`, `pest_plugin.rs` callers, `phpcs_installer.rs`:
   `layout.vendor_dir()` / `composer_dir()` instead of `project/vendor`;
   `vendor_composer_dir(layout)`.
5. `crates/vivacity-autoload/src/generator.rs`: `vendor_dir` from the
   layout; `install_abs` strips `vendor_rel/`; nothing else changes (the
   path codes already go through `find_shortest_path_code`). Oracle test
   in `tests/oracle_*`: a project with `lib/vendor` → `$baseDir =
   dirname($vendorDir, 2)` compared to Composer's output (the harness
   covers it end to end; the unit test pins the code string).
6. `crates/vivacity/src/lib.rs`, `require.rs`, `extension_installers.rs`:
   the ~12 `project.join("vendor")` sites → the layout's directories;
   where no layout exists yet (`installed.json` read before the lock,
   fresh-install detection, fallback decision), `Dirs::resolve` once at
   command start and passed down.
7. `crates/vivacity-core/src/scope.rs`: `config_issues` keeps only
   `preferred-install`; tests; `--check-scope` help text.
8. `harness/vendor-dir.sh` (new, modelled on `path-repos.sh`): stages a
   fixture copy, patches `composer.json` `config` with `jq`, runs the
   three steps per variant, compares with `compare_vendor` on the project
   directory (and `.bin` names in the inventory). `harness/corpus.sh`:
   compare the whole project when `config.vendor-dir` or `bin-dir` is set.
   `.github/workflows/ci.yml`: the new harness in the parity job.
9. Docs (success criterion 5); `docs/corpus/<date>.md` from the re-run.

### Order

dirs.rs (TDD) → layout → binproxy → installer/state/plugins → generator →
CLI sites → scope → cargo test + clippy + fmt → harness/vendor-dir.sh
(expect the first run to find the sites I missed) → existing harnesses →
corpus --only → docs → CI.

- After step 8: `harness/vendor-dir.sh` 0 diff on all variants.
