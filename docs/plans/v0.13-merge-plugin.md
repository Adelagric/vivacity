# v0.13 — `wikimedia/composer-merge-plugin`, emulated without its implicit update

Started 2026-09-17. Level 2 (a plugin that rewrites the lock; a
deliberate deviation from Composer): fresh-subagent meta-analysis,
independent review.

## 1. Scope

### Problem

Five corpus projects (concretecms, invoiceninja, leantime,
open-web-analytics, salesagility-suitecrm-core — v2.1.0, concretecms
v2.0.1, same semantics) fall back for `wikimedia/composer-merge-plugin`,
the first plugin in the ranking after v0.11. The plugin merges the
`composer.json` files named by `extra.merge-plugin.include` / `require`
(PHP `glob()` patterns) into the root package in memory. What that changes
on disk on an `install`: the autoloader (PSR-0/4, classmap, `files`,
`exclude-from-classmap` of the included files, paths re-based on each
file's directory) and `installed.php` (the root's `provided` / `replaced`
targets); with `merge-extra`, the root `extra` (installer paths); and the
lock validation against the root requirements.

### Reference (plugin v2.1.0, vendored under
`docs/reference/plugins/composer-merge-plugin/`, MIT)

- `MergePlugin::getSubscribedEvents`: INIT, POST_PACKAGE_INSTALL,
  POST_INSTALL_CMD, POST_UPDATE_CMD, PRE_AUTOLOAD_DUMP, PRE_INSTALL_CMD,
  PRE_UPDATE_CMD — all at priority 50000. `--no-scripts` does not silence
  them (plugin listeners run regardless).
- `PluginState::loadSettings`: defaults `include: []`, `require: []`,
  `recurse: true`, `replace: false`, `ignore-duplicates: false`,
  `merge-dev: true`, `merge-extra: false`, `merge-extra-deep: false`,
  `merge-replace: true`, `merge-scripts: false`; a string `include` is a
  one-element list. `isDevMode() = mergeDev && devMode`.
- `mergeFiles(patterns, required)`: `array_map('glob', $patterns)` — PHP
  `glob()` with **no flags** (no braces, files and directories, sorted by
  libc per pattern); a `require` pattern matching nothing throws
  `MissingFileException("merge-plugin: No files matched required '{p}'")`.
  `include` patterns first, then `require`; a path merged once is not
  merged again (`loaded` / `loadedNoDev`).
- `ExtraPackage::mergeInto`: `prependRepositories`, `mergeRequires('require')`
  (stability flags, `self.version` replaced by the root's version or
  constraint, then `mergeOrDefer`: a duplicate key is ignored
  (`ignore-duplicates`), replaced (`replace`), or **conjoined** — the
  pretty constraint becomes `"<old>, <new>"`, `Intervals::isSubsetOf`
  short-cuts to one side), `mergePackageLinks('conflict')`,
  `'replace'` (if `merge-replace`), `'provide'` (`array_merge`: the
  include wins on a duplicate key), `mergeSuggests`,
  `mergeAutoload('autoload')` (**`array_merge_recursive`** of the raw
  autoload arrays with paths prefixed by `dirname($path) . '/'` — a
  duplicate PSR-4 key yields a list of paths, lists append),
  `mergeExtra` (only with `merge-extra`; `array_merge($extra, $rootExtra)`
  — root wins — or the include wins with `replace`; `NestedArray::mergeDeep`
  with `merge-extra-deep`; `extra.merge-plugin` of the include stripped),
  `mergeScripts` (only with `merge-scripts`); then in dev mode
  `mergeDevInto`: `require-dev`, `autoload-dev`. Recursion
  (`recurse`): the include's own `extra.merge-plugin.include/require`,
  re-based on its directory, after it is merged.
- **On a bare vendor** the plugin is installed during the transaction,
  activated at once, receives POST_PACKAGE_INSTALL for itself
  (`firstInstall`), merges at PRE_AUTOLOAD_DUMP, and at POST_INSTALL_CMD
  runs `Installer::create(...)->setUpdate(true)->setUpdateAllowList(<merged
  requirement names>)` — a partial `composer update` against the live
  repositories that **rewrites composer.lock** (measured on
  open-web-analytics with its real module files: maxmind-db/reader
  1.13.1 → 1.14.0, monolog 2.11.0 → 2.11.1, symfony/filesystem 7.4.15 →
  7.4.18, +28/−27 lock lines) and installs the result. With the plugin
  already in `installed.json` (warm vendor) nothing of the sort happens:
  the merge is applied from INIT and the lock is validated against the
  merged requirements like any root requirement (`Your lock file does not
  contain a compatible set of packages` when one is missing).
- Composer's own steady state is therefore: root merged, lock as
  committed, autoloader and `installed.php` from the merged root.

### Decision (2026-09-17, with the user): deterministic, never the implicit update

vivacity emulates the merge and validates the lock against the merged
requirements; it **never** runs the plugin's implicit partial update nor
rewrites the lock during an `install`. A lock that does not satisfy the
merged requirements is handed to Composer with the reason (Composer does
its update there; vivacity will not do that on a user's behalf). Rationale
in DECISIONS: Composer's cold-vendor result depends on the registry at
that instant — not reproducible even by Composer; at a frozen registry
its implicit update is a no-op and its output equals vivacity's, so the
parity is provable; the precedent of `pest-plugins.json` and the `files`
order (vivacity writes the deterministic form and says so).

### Constraints

- Byte-identical to Composer's steady state (warm plugin, committed lock)
  in both dev modes: autoloader (plain, `-o`, `-a`), `installed.json`,
  `installed.php`, whole project.
- Same gating as the other emulations: plugin in the lock (wanted for
  the mode), allowed by `allow-plugins`, plugins enabled; `--no-plugins`
  → no merge (Composer loads nothing).
- `vivacity update` / `require` / `remove` on a project with an active
  merge configuration are refused (they would resolve without the merged
  requirements and repositories) — a scope issue with the reason, not a
  wrong lock. Emulating the merge for resolution is a later plan.
- The corpus fixtures must carry the included files for the emulation to
  be exercised at all (today the plugin is a silent no-op on them).

### Non-goals

- The implicit update (above). `merge-scripts` (scripts never run),
  `mergeSuggests` (no output on install), aliases/references extraction
  (resolution only), `prependRepositories` (resolution only).
- Composer 1 branches of the plugin (`isComposer1`).
- `vcs`/`path` repositories declared in included files (resolution).

### Success criteria (observable)

1. Fixture `fixtures/projects/merge-plugin` (hand-written, lock generated
   by Composer once with the plugin active, `tools/snapshot-packagist.sh`
   snapshot): root with `extra.merge-plugin` (`include`: a glob and a
   literal, `require`: one file, `recurse: true`, defaults otherwise),
   three included manifests — one with PSR-4 + `files` + classmap +
   `exclude-from-classmap` + `provide` + `replace` + `conflict` + a
   duplicate `require` key with another constraint, one with
   `autoload-dev` + `require-dev`, one nested include (recursion, `..`
   free), plus a `self.version` link; a variant manifest with
   `ignore-duplicates`, one with `replace`, one with `merge-extra` +
   `installer-paths` (composer/installers in the lock), one with
   `merge-dev: false`.
2. `harness/merge-plugin.sh`: for each variant, Composer's steady state
   (`composer install --no-plugins`, then `composer install` — plugin now
   active from INIT; the lock asserted unchanged) against one
   `vivacity install --no-fallback` on a bare vendor; then `dump-autoload
   -o`, `-a`, `--no-dev` install; whole project compared. Plus: a lock
   missing a merged requirement → vivacity falls back with the reason
   (`--no-fallback`: exit 3, the line printed), and `vivacity update` on
   the fixture → refused with the reason. In `ci.yml`.
3. `tools/corpus-add.sh` keeps the files matched by the merge globs (and
   their autoload paths as `.gitkeep`/copies, recursively); the five
   entries re-fetched at their pinned commits; `harness/corpus.sh` builds
   the reference as the steady state when the plugin is allowed; full
   corpus re-run: the five entries native (or their other reasons only),
   0 diff, report regenerated.
4. Unit tests: the merge on JSON values (each section, duplicate rules,
   path re-basing, recursion, `self.version`, `merge-extra` shallow/deep,
   `merge-dev: false`), the PHP-flag-less glob (files, no braces, sorted,
   `require` miss).
5. Docs: README (plugins paragraph: seven emulated, the deviation in one
   sentence), NOTICE (plugin MIT), HANDOVER, DECISIONS, CHANGELOG,
   CONTRIBUTING, `docs/reference/plugins/composer-merge-plugin/`, this
   plan; corpus report.

## 2. Plan

### Files

1. `docs/reference/plugins/composer-merge-plugin/` — `MergePlugin.php`,
   `ExtraPackage.php`, `PluginState.php`, `NestedArray.php`,
   `StabilityFlags.php`, `LICENSE` (v2.1.0; the v2.0.1 diff is
   `array()` syntax and a lock backup — noted in the README of the dir).
2. `crates/vivacity-core/src/glob.rs`: `glob_files(pattern, base) ->
   Vec<String>` — PHP `glob()` with flags 0: no brace expansion, files and
   directories, no `GLOB_MARK`, `.`-hidden excluded, sorted bytewise,
   pattern spelling kept; shares `glob_one` with `glob_dirs`. Tests.
3. `crates/vivacity-core/src/merge_plugin.rs` (new):
   - `pub const PLUGIN_NAME`; `Settings::from_manifest(&Value)` (the
     defaults above);
   - `pub fn merged_manifest(project_dir, manifest: &Value, with_dev:
     bool) -> Result<Value, String>`: returns the root manifest with the
     merged sections (`require`, `require-dev`, `autoload`,
     `autoload-dev`, `conflict`, `replace`, `provide`, `extra`) as a
     `serde_json::Value`, the input untouched when no file matches;
     `Err` = scope issue (`require` pattern without match: Composer's
     message; a file that is not valid JSON: `JsonFile` error text).
     Order and rules exactly as `mergeFiles` / `mergeInto` /
     `mergeDevInto`; `loaded` de-duplication by path; recursion.
   - `fn rebase(paths: &Value, base: &str)` (`fixRelativePaths`),
     `fn array_merge_recursive(a, b)` (PHP semantics on JSON: string
     keys merge recursively into lists, integer keys append),
     `fn array_merge`, `fn merge_deep` (NestedArray), `fn
     merge_requires(origin, merge, settings, merged_names)`,
     `fn replace_self_version(links, root)`.
   - Unit tests (criterion 4).
4. `crates/vivacity-core/src/scope.rs`: `wikimedia/composer-merge-plugin`
   in EMULATED_PLUGINS; `analyze` calls `merged_manifest` when the plugin
   is active and turns its `Err` into `ScopeIssue::Plugin`-style issue;
   `pub fn merge_active(lock, manifest, with_dev, plugins_enabled) -> bool`
   (locked + wanted + allowed + enabled).
5. `crates/vivacity/src/lib.rs`: `run_install` and `run_dump` compute the
   effective manifest once (`merge_plugin::merged_manifest` when active)
   and pass it to `Layout::resolve`, the installer (`root_manifest`),
   `write_state_files`, the generator, the plugin emulations, and to the
   lock check — `install_policy_problems` gains a `manifest: Option<&Value>`
   argument (session.rs reads composer.json itself today); when the merge
   is active and the problems are non-empty: the fallback with the reason
   `wikimedia/composer-merge-plugin: the lock does not satisfy the merged
   requirements (<names>); Composer would run the plugin's implicit update
   and rewrite composer.lock` instead of the error. `--check-scope`
   reports it the same way. `run_update`, `run_require`, `run_remove`: if
   `merge_active` → `anyhow::bail!` with the reason (no native
   resolution).
   The content-hash stays computed from the file text (the plugin never
   touches it).
6. Fixture: `fixtures/projects/merge-plugin/` (+ `fixtures/make.sh`
   entry or a hand-built lock committed like `solver-*`; registry
   snapshot `fixtures/registry/merge-plugin.tar.gz` via
   `tools/snapshot-packagist.sh`), variants as jq patches in the harness
   like `vendor-dir.sh`.
7. `harness/merge-plugin.sh` (criterion 2), `ci.yml` step.
8. `tools/corpus-add.sh`: after the autoload paths, `jq` the
   `extra.merge-plugin.include/require` patterns, resolve them with PHP
   (`php -r 'foreach (glob($p) as $f) echo "$f\n";'` — the machine has
   php) recursively, copy each file, then apply the autoload-path logic to
   each included manifest with its directory as prefix. Re-fetch the five
   entries (`tools/corpus-add.sh git <url> <name>` with the pinned commit
   from PROVENANCE — check the script accepts a ref). `harness/corpus.sh`
   `run_one`: when `jq .config["allow-plugins"]["wikimedia/composer-merge-plugin"] == true`
   and `extra.merge-plugin` exists, the reference is `composer install
   --no-plugins …` then `composer install …` (lock asserted unchanged,
   else `unavailable` with the reason).
9. Docs (criterion 5).

### Order
