# v0.15 — Where the milliseconds go on `install`, and the four that pay

Decided on 2026-09-18. The update-with-plugins plan (formerly v0.15) moves
to v0.16, untouched. Method for every step below: one change, measured
before/after on the same machine and profile, harnesses green, a DECISIONS
entry with the numbers and the conditions. No step starts before the
previous one's numbers are written.

## 1. Framing

**Problem.** A no-op `vivacity install` on Laravel costs 103–125 ms on Linux
(arm64 container, php:8.4) and 119 ms on macOS (M4 Max); a warm reinstall
130–150 ms / 219 ms. Traced (`VIVACITY_TRACE=1`, 2026-09-18):

| phase | Linux no-op | Linux no-op `--offline` | Linux warm `--offline` | macOS no-op `--offline` |
|---|---|---|---|---|
| manifests | 1.5 | 1.4 | 1.2 | 1.2 |
| policy (lists, one conditional request) | **73–92** | 8 | 5 | 7 |
| platform (cached since 0.14) | 0.5 | 0.4 | 0.4 | 0.4 |
| scope | 12–14 | 9 | 4 | 11 |
| transaction | 6–7 | 5 | **30** (hardlinks) | 7 |
| autoload dump | 9–10 | 8 | 7 | **53** (`-o`: root psr-4 scan) |

Facts that bound the work:
- The network cost is one conditional request for the filter summary
  (`If-Modified-Since`, 304), `packages.json` being taken from cache under
  600 s — exactly Composer's `loadFilterSummary` / `loadRootServerFile(600)`.
  It is sequential: nothing else runs while it waits.
- With `--offline`, the Linux warm is 47 ms; the whole online/offline gap is
  that request.
- `optimize-autoloader: true` (Laravel's default config) makes every install
  scan the root psr-4 directories; the classmap cache only covers store
  entries.
- A no-op short-cut on "lock content-hash + composer.json hash" is refused
  (DECISIONS 2026-09-18): it skips the dump, and `composer install` picks up
  a class added under a root `classmap` / `-o` psr-4 directory.

**Constraints.** Byte-identical output and identical stderr order (steps.sh
compares stderr on 229 cases); the policy decision (exit 2 on a blocked
locked version) is taken before any write, as in `Installer::doInstall`;
the list request stays a per-install conditional request (parity with
Composer — a TTL is a separate contract decision, not taken here).

**Non-goals.** The resolver (`update` is already ahead of Composer: 1.00 s vs
1.07 s on Laravel), CI cache artefacts (bench/M7), SAT internals, cold
installs (network-bound, parallel already).

**Success criteria** (Laravel, `--no-plugins --no-scripts`, hyperfine, same
machine): Linux no-op online ≈ max(request, work) instead of their sum
(target ≤ 95 ms from 103–125); macOS `-o` dump 53 → ≤ 15 ms with a
modified root file still rescanned and an added one still found; no-op
`--offline` ≤ 15 ms on Linux with the fingerprint; steps/diff-vendor/
update/path-repos/scripts harnesses 0 diff; gate ratios not worse.

## 2. Steps

### P1 — Overlap the list request with the local work (no contract change)

`run_install`: spawn the policy check (`install_policy_problems`) on a
thread right where it runs today; compute — without printing — the
platform check, the scope analysis and the transaction; join; then emit
in today's order: policy warnings, policy problems (exit 2), platform
failures (exit 4), scope notes / fallback, transaction summary. Nothing
is written before the join. Files: `crates/vivacity/src/lib.rs`
(run_install only). Gate: steps.sh (stderr order), diff-vendor, a case
with a blocked locked version (existing policy cases in steps.sh) still
exits 2 with identical text. Expected gain: the overlapped work
(15–40 ms on Linux, more on macOS with `-o`).

### P2 — Per-file cache for the root scans (`-o`, root `classmap`)

The classmap scanner keeps a per-store-entry cache; add a per-file cache
for paths outside the store, keyed on (canonical path, mtime ns, size) →
classes found. Directory listing stays real (an added or removed file is
seen); a changed file is rescanned; the cache lives under the classmap
cache directory, binary format like `CACHE_FORMAT`, `VIVACITY_NO_CLASSMAP_CACHE=1`
disables both. Files: `crates/vivacity-autoload/src/classmap*.rs` (where
the store cache is), generator call sites. Gate: diff-vendor
`--with-autoloader` twice (cold then warm cache), a harness step that
adds / edits / removes a root class between two installs and diffs
against Composer (new case in `harness/scripts.sh` or `steps.sh`).

### P3 — REFUSED (2026-09-18, DECISIONS): no fingerprint short-cut

The adversarial review found five inputs the record missed (dump warnings
replayed by Composer on every no-op, an absent psr-4 dir later created,
the global config.json, the runtime template, LICENSE / include_paths.php
among the outputs) and a cost fact (the hit would cost about the scan).
Replaced by:

### P3b — Dump without redundant work (no contract change)

One consolidated store-cache file per lock (the ~250 per-entry loads become
one read; same immutability assumption), and `autoload_static.php` emitted
directly in its final form instead of var_export → substitution →
re-indentation over ~1 MB. Gate: diff-vendor `--with-autoloader` twice,
root-scan.sh, steps.sh; target Linux `dump -o` 19 → ~8 ms.

### P3c — Dump computed during the network wait

When the transaction is empty, every input of the dump is known before
the policy join: compute the autoloader in memory on the main thread while
the request runs, write (byte-compare, as `write` does) after the join,
print the dump's warnings where they are printed today. Online no-op
≈ max(request, everything else). Gate: stderr identical (steps.sh),
diff-vendor, the trace shows the dump timestamp before the join.

### P4 — Scope without double reads

`run_install` parses the lock twice (`Lock` + `Value`), reads the global
config in several places and installed.json more than once. Read once,
pass references. Files: `lib.rs`, `vivacity-core::layout`. Gate: unit +
harnesses; expected 3–5 ms.

## 3. Meta (self-checklist for P1/P2/P4; fresh reviewer for P3)

- P1: every print between the spawn and the join must move after the join
  in the same relative order; `--dry-run` and `--check-scope` paths go
  through the same join; a panic in the thread must surface as the same
  error text; `--offline` still prints its warning at the same place.
- P2: mtime granularity (1 s on some filesystems) — key on size too and
  on mtime *nanoseconds* where available; a file replaced within the same
  second with the same size is the documented residual risk (same as the
  store cache assumes vendor/ immutable). Symlinked roots: key on the
  canonical path.
- P3: enumerate the dump's inputs from `AutoloadGenerator::dump`'s port,
  not from memory; the reviewer lists what is read and checks the
  fingerprint covers each item.

## 4. Execution log

(filled as each step lands: numbers before/after, machine, commit)

- **P1** (2026-09-18): policy on a thread, platform/transaction/scope
  computed before the join, report in Composer's order. Linux container
  (arm64, php:8.4): trace shows scope timestamp == join (≈10 ms overlapped);
  hyperfine no-op online 128 → 117 ms, warm 128 vs 131 (σ 12–43 ms of
  network noise — the gain is deterministic in the trace, invisible to
  hyperfine here). macOS: 13–18 ms overlapped. stderr byte-identical,
  286 harness cases and 214 tests green.
- **P2** (2026-09-18): the root-scan cache (`FileCacheSlot`, `ScanCache`,
  `harness/root-scan.sh` 9/9) was not where the time went — profiling
  (`sample` on an in-process loop) found `BTreeSet<PathBuf>` comparisons
  (28 % of the dump), a byte-by-byte `replace_bytes`, per-file
  `normalize_path` allocations, per-class `format!`, per-job regex
  compilation. Fixed together. `dump-autoload`: macOS 61.5 → 28.1 ms;
  Linux `-o` 39.7 → 19.4, no-op `--offline` 53.2 → 34.7, warm `--offline`
  72.5 → 53.1. Output byte-identical (298 harness cases, 214 tests).
- **P3b** (2026-09-18): one-pass static emitter measured at 28.1 → 28.0 ms
  (no gain, the memmem substitution had already paid) → reverted; store
  cache consolidation not done (scan phase 4 ms, allocation-bound). The
  dump profile is flat now.
- **P3c** (2026-09-18): `plan` / `DumpPlan::commit` split; the plan is
  computed before the policy join when the transaction is empty
  (`local_repository_if_unchanged`). Online no-op: macOS 141.7 → 116.4 ms,
  Linux 106.5 → 94.7; the trace shows the plan done at 30–44 ms and the
  request back at 82–100. Offline +1.6 ms on Linux (one more
  installed.json read, P4). stderr identical, 311 harness cases green.
