# vivacity-pcre2-sys

[pcre2-sys](https://github.com/BurntSushi/rust-pcre2) 0.2.10 (PCRE2 10.46
with sljit), built **always from the vendored source** and with **every
symbol prefixed `vivacity_`**. It is the regex engine of
[vivacity](https://github.com/Adelagric/vivacity) through
`vivacity-pcre2`; nothing else should need it.

## Why

A program that embeds vivacity (`vivacity::run` in-process) and links a
PCRE2 of its own — PHP's `libphp.a` bundles one, with the usual
`pcre2_compile_8` / `_pcre2_check_escape_8` names — cannot link two
copies of the same symbols. Taking the system library instead (what
pcre2-sys does when pkg-config finds one) only moves the problem to hosts
without it, and makes the binary depend on that library. A prefix at the
source removes vivacity's side of the conflict everywhere.

## What differs from pcre2-sys 0.2.10

- `upstream/include/pcre2.h`: `PCRE2_SUFFIX` (both definition sites: the
  three-width generation and the application one) also prepends
  `PCRE2_SYMBOL_PREFIX` when that macro is defined; a new
  `PCRE2_TYPE_SUFFIX` keeps `PCRE2_UCHAR` / `PCRE2_SPTR` on their literal
  typedefs. Without `PCRE2_SYMBOL_PREFIX` the exported symbols are
  byte-identical to the base.
- `upstream/src/pcre2_internal.h`: the six width-independent private
  symbols (`_pcre2_ckd_smul`, `_pcre2_utf8_table1..4`,
  `_pcre2_utf8_table1_size`) get the prefix explicitly.
- `build.rs`: no pkg-config branch, `PCRE2_SYMBOL_PREFIX=vivacity_`, the
  archive is `libvivacity_pcre2.a`.
- `src/bindings.rs`: every `pub fn pcre2_*_{8,16,32}` carries
  `#[link_name = "vivacity_…"]` (generated by
  `tools/prefix-pcre2-bindings.py` in the vivacity repository).
- `src/lib.rs`, everything else under `upstream/`: unchanged.

`tools/check-pcre2-symbols.sh` (repository) asserts that the built
archive exports nothing without the prefix (137 globals as of 10.46);
`crates/pcre2-link-test` links a foreign, unprefixed PCRE2 stub next to
this crate and runs a match.

## Rebasing on a newer pcre2-sys

Copy `upstream/`, `src/bindings.rs`, `build.rs` from the new release;
reapply the two header patches (`git diff` of this crate shows them);
run `tools/prefix-pcre2-bindings.py`; rebuild and run
`tools/check-pcre2-symbols.sh` and `cargo test -p pcre2-link-test`.
